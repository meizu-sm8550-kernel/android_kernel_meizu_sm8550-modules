# M2468 MP 默认180Hz触控命令

仅对现有 `goodix,brl-d` 且根 `meizu,board-id=<3 5>` 的 M2468 MP profile，恢复原厂 probe 使用的默认上报率命令：`len=5 / cmd=0x9d / parameter=2`。沿现有 IC 元数据取得命令地址，由 `send_cmd` 生成校验和并等待 ACK；不硬编码寄存器或启用游戏模式。参数2是模式编号。

正常固件与配置就绪后初始化；正常复位、成功重新上电（含ESD恢复）和实际配置下载成功后恢复。挂起期间不发送，普通及手势唤醒在共用出口解除挂起阻止；固件更新与移除使用独立阻止标志，resume不能解除它们。短ISP复位、复位/上电失败、正常元数据无效时不发送。配置ID相同而跳过下载时没有新配置边界，不重复发送。

M2468固件RESET/CONFIG请求仅在IRQ线程排队，由工作线程按先reset后config处理；触点MOVE、坐标六处/10、压力/面积、触点ID和事件顺序保持。完整复位/电源/配置会话与速率恢复互斥；命令写入与ACK另行串行。生命周期关闭gate后同步IRQ、排空工作，旧请求不跨休眠/升级/移除重放。没有新增手势或FOD事件，不改变framework gate、HBM、UI-ready。

命令失败保留错误日志和基本触控，沿用现有有限ACK重试，不无限重试；仅下一次真实恢复边界再尝试。成功日志 `M2468 MP default 180Hz command acknowledged` 仅证明命令ACK，不等于实测输入已经180Hz。

本地主机回归执行真实校验和、发送/ACK、恢复与生命周期函数：覆盖动态地址、精确字节、profile、失败复位/上电、ISP门控、并发排空及IRQ延期；原真实手指上报函数回归保持。独立增量候选通过129项导入CRC、导出ABI、CFI/MODVERSIONS/ThinLTO检查，388项选择仅替换Goodix。主机测试中的总线/内核调度替身不构成实机通过。

现有坐标修复已由用户确认。新的180Hz候选仍需用户自行构建并更新镜像，核对运行模块身份、profile/ACK日志，再人工连续拖动比较输入间隔和144Hz新画面呈现节奏，回归亮灭屏、坐标/多点/旋转及指纹/HBM。尚未实机A/B，不能宣称TIM、惯性或全部顿挫已经修复。

服务器只需同步 `kernel/meizu/sm8550-modules` 后继续 `mka bacon`；保留out、ROM默认Clang和已有manifest。独立维护层基于已成功的坐标候选和388项选择，保留所有历史产物；它不修复旧fingerprint/HBM链的历史camera哈希缺口。
